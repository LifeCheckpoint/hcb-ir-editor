# 资源接线

一句话：**块参数是事实，文件是投影。** 接线断了只影响显示和预览，不改写参数。

## 保存什么

项目文件里只存：

- 章节 / 场景 / 块，块的 `data` 就是 DSL 参数原文（`[bg,67]`、`[bs,3,1,3,17]`、`[cg,KURO_e011a1]`、`[se,209]`……）；
- 绑定表（名字 → 调用 → 备注）；
- 映射表（TOML 路径 + 内嵌内容）；
- 游戏目录路径；
- UI 状态（工作区、当前章节、折叠的小节）。

不存：解析出来的文件路径、偏移、缩略图、`已接/断线` 状态。这些每次打开重新算。

原因很直接：换机器、换一份游戏拷贝、没扫到目录时，项目仍然能打开、能保存；文件路径不会过期，也不会把 A 机器的路径带到 B 机器。

## 免封包资源

FVP 允许免封包：扫描根目录时会同时看 `.bin` 和与它同名的散装文件夹，例如 `graph_bg/`、`voice/`。

- 同名文件夹里的文件优先级高于归档里的同名条目；资源管理器合并后只显示散装版本。
- 只有文件夹、没有 `.bin` 的已知资源组也会建组；未知目录不扫。
- 散装文件没有归档偏移，按整文件读取；PNG/JPEG/GIF/WebP 可直接预览，Ogg/WAV 可直接播放。
- 资源管理器左侧会在组名后标「（散装）」，条目偏移显示为「—」。

## 解析顺序

1. 映射表（TOML）：所有资源类型的唯一编号层；优先级最高。
2. 剧本声明：只对自定义资源兜底，`bgload` 的 `id,file,name` 和 `cgload` 的 `name`。
3. 扫描到的归档或散装文件：只把条目名变成偏移、缩略图、格数，不参与编号猜测。
4. 没有第四层；不再读领域表，也不再按 `BG%03d` 或三位补零猜。

项目绑定表是另一层：名字 → 调用，主要给资源区看，块参数不依赖它（以后可以让块优先用同名绑定，但不是现在的行为）。

解析是纯函数，不写回块。

## 断线时

- 块保留 DSL 参数，界面上仍然是原来的编号或名字，不会变成空值。
- 右栏「接线」一行给出状态：绿点 + 映射链（`映射表 背景 67 → BG067_000 → graph_bg.bin`），或者土色 + 断在哪一层（`映射表没有 背景 501；bgload 天空1 → BG501；graph_bg.bin 里没有`）。
- 之下仍然可以手动选另一个背景 / 立绘 / CG；这是显式改写参数，导入和打开项目都不会自动改写。
- 绑定表是项目级的名字层；某条绑定解析失败，不影响引用它的块保存。

这样即使 DSL 只导入了一半（缺 `bgload` 声明）、或者资源目录里少了某个归档，项目也不会丢参数；补上目录或声明后，同一份项目会自己恢复解析。

## 映射表

`mappings/sample.toml` 是字段示例；`mappings/sakura.toml` 是从 `Sakura.hcb` 生成的完整表（24 角色 / 99 立绘 / 62 背景 / 238 CG / 70 BGM / 304 音效）；`mappings/zhongxiaye.toml` 是《祈愿与仲夏日之梦》的专用表（5 角色 / 17 立绘 / 18 背景 / 16 CG / 19 BGM / 18 音效 / 266 语音，显式写 `bs`）。导入后存进项目文件，路径和内嵌内容都保留；解析不到时仍保留 DSL 参数。所有资源编号都只来自表，不再依赖 `cha_list` 的顺序、归档出现顺序或命名约定。没有映射表时，资源字段退回数字/文本输入。

立绘编号来自 hcb `f_00058B8C` 的 `a1/a2/a3`；`cloth` 从 0 开始。完整表的 `cha=14` 是 `CHR_ハル２`，旧推断会把它当成大雅。`faces` 只表示表情表格数，不是 hcb 的 `a4` PartsSelect 编号。`voice` 段已留，完整表暂时 0 条：DSL 的 voice 是 hcb 语音表序号，不是 `voice.bin` 的 8 位文件号。`sprite` 行可以额外写 `bs`：它是剧本 `[bs]` 的第一个参数，旧表省略时等于 `cha`。同人游戏/改表后两者可能不同（本作 `bs=3` 是落叶，原版 `cha=3` 是千和），这时必须在每行写 `bs`，否则预览会按原版角色找图。

## 背景编号

内置编号的文件名是 `BG` + 三位补零：

| 编号 | 文件 |
|---|---|
| 12 | `BG012_000` |
| 67 | `BG067_000` |
| 75 | `BG075_000` |
| 112 | `BG112_000` |

已用真实 `graph_bg.bin` 核对过。每个编号下有 `_000` / `_000b` / `_001` / `_010` / `_100` 等变体，默认取 `_000` 作底图。完整表按 hcb 的 `a7` 生成了 `bg.variants`：`diff=1` 是底图，`diff=2/3` 选默认变体；旧式 `[[bg.variant]]` 仍兼容；`a9/a10=100` 的时段/天气分支需要额外参数，DSL 的 `diff` 不覆盖。

自定义编号走 `bgload`：

```text
[bgload,500,BG500,校门]
```

自定义编号只走映射表或 `bgload` 的显式文件名，没有 `BG%03d` 兜底。内置编号的 `bg` 行由完整表提供；没写进行里的编号就是断线，界面会直接说「映射表没有 背景 N」，而不是去归档里碰运气。

同一个编号被两份脚本重复声明时，后出现的那份生效（和 `declarations()` 一致）；目前不会拦住导入，项目体检以后会报这个冲突。

## 已经接上的

- 映射表：资源工作区可导入 TOML，存进项目并记住路径；角色、立绘编号、背景、CG、BGM、音效、voice 段都走它。
- 模拟预览里的 `bg`：背景图直接从 `graph_bg` 取，取不到就保留底色并标断线。
- 模拟预览里的 `cg`：CG 名在 `graph_vis` / `graph_vish` 里命中就显示真图。
- 资源区绑定表的 `bg` / `bs` / `cg` / `se` / `bgm` 行：从表查行再落到归档，断线原因也按映射链显示。
- 右栏「接线」：`bg` / `cg` / `bs` / `se` / `bgm` 五类给出映射链或断在哪一层。

## 还没做

- 统一的引用注册表：接线仍按原语分支拼链（`bg` / `cg` / `se` / `bgm` 走 `wiring.js`，`bs` 直接查 `mapping.js`），还没有单一个 ref 对象。
- 断线后的「重新链接」按钮、绑定编辑 UI、映射表的逐条编辑（现在只能整份 TOML 导入）。
- 背景的时段/天气变体（`a9/a10=100` 的 `_100` / `_120`）：DSL 的 `diff` 只到 a7，这些需要额外参数。
- 项目体检：一次列出全稿所有断线的块。
